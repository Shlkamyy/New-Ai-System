# Explicit app installation control

The application had a manifest, icons and a registered service worker, but no in-app install action or `beforeinstallprompt` handler. The browser menu was the only installation entry point. Added an install button with the Dr Mai icon to both login and sidebar, outside the login form.

When Chromium supplies `beforeinstallprompt`, the button invokes that actual browser event. An accepted prompt is not represented as completed installation: only `appinstalled` or current standalone display mode hides the control. Prompt failures/absence offer a working manual installation path; iOS/iPadOS describes Safari Share → Add to Home Screen, other browsers describe their Install/Add to Home Screen menu. No authentication or clinic record mutation is needed. The sidebar retains the existing final Logout control and permission-scoped groups.

Browser policy, supported platform, Preview protection and engagement requirements may determine whether a native install prompt is available. This code cannot force installation, launch an OS installer, or guarantee an app-store/native-device installation. Manual guidance appears only after the user activates Install, not as permanent onboarding copy.

A real Android/iOS OS-level install was not executed. Service-worker shell version is v7. No new dependency or migration was added; production remains unchanged. A later Preview deployment publishes the button with existing QA configuration.
